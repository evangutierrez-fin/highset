# Spec: performance budgets

Requirements: PERF-1…10 (PRD §8.1). ADRs: 0017.

The owner's one stated deal-breaker is an app that is slow or heavy (Q13.9). These budgets are **release-blocking**: a regression fails CI (smoke thresholds) or blocks the release (full measurement).

## 1. Budgets

Reference machines: an Apple M1 (or newer) Mac with 16 GB, and a mid-range x86_64 Linux laptop. Dataset: generated by `xtask perf gen` with 10k tasks across 20 projects, 10k knowledge items, 1k sessions with transcripts, and 50k fuzzy candidates.

| ID | Metric | Budget | How it is measured |
|---|---|---|---|
| PERF-1 | TUI start → first frame (daemon running) | ≤ 150 ms p95 | `xtask perf tui-start`: spawns the TUI with `HIGHSET_PERF_EXIT_AFTER_FIRST_FRAME=1`, 30 runs |
| PERF-2 | Keypress → frame rendered | ≤ 16 ms p95, also with 4 sessions flooding output | TUI bench harness with synthetic events (no real terminal) + manual check |
| PERF-3 | One-shot CLI (`highset add`, `task list --json`) | ≤ 60 ms p95 | `hyperfine` in `xtask perf cli` |
| PERF-4 | Daemon idle CPU | < 0.5% average over 5 min; no timers > 1 Hz | `xtask perf idle` samples `/proc` or `ps`; code review rule |
| PERF-5 | Daemon idle RSS | ≤ 60 MB (agents excluded) | same |
| PERF-6 | TUI RSS with 4 attached sessions | ≤ 80 MB | same |
| PERF-7 | Fuzzy palette per keystroke (50k candidates) | ≤ 10 ms | criterion bench in `highset-search` |
| PERF-8 | Full-text query (10k docs) | ≤ 50 ms p95 | criterion bench |
| PERF-9 | Full reindex (10k docs) | ≤ 10 s | `xtask perf reindex` |
| PERF-10 | Release binary size (stripped) | ≤ 40 MB | CI release job |

Secondary targets (not release-blocking):

- `context.compile` cold ≤ 100 ms, warm ≤ 5 ms;
- `ui.bootstrap` ≤ 40 ms;
- `mention.complete` ≤ 30 ms;
- MCP tool overhead ≤ 10 ms.

## 2. CI

- **Smoke perf job** on Linux CI runs PERF-3, PERF-7, PERF-8 and PERF-9 with **2× budget thresholds**, because CI machines vary. It fails on breach.
- **Full measurement** (R-001) on the reference machines before each release. Results are committed in `docs/perf/<version>.md`.

## 3. Design rules (apply from the first task)

1. No polling loops. React to events: the fs watcher, process IO, sockets.
2. Render on dirty only, coalesced; virtualize lists; never rebuild the whole UI tree for one change.
3. Keep the TUI process thin. Heavy work (indexing, parsing, compiling context) happens in the daemon.
4. Cache by content hash (context bundles, parsed files); invalidate on watcher events.
5. SQLite: WAL, prepared statements, one connection actor, transactions for batches. Never query inside a render loop.
6. PTY output: ring buffers, coalesced notifications, and no persistence of raw bytes by default.
7. Allocate deliberately in hot paths (render, fuzzy, redaction); measure before optimizing elsewhere.
8. Dependencies: justify heavy crates; put rarely used heavy features (e.g. syntax highlighting, PDF extraction) behind lazy init or cargo features if they threaten PERF-1 or PERF-10.
9. Release profile: `lto = "thin"`, `codegen-units = 1`, `strip = true`, `panic = "unwind"` (needed for terminal restore).
